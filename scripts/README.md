# Скрипты

## Окружение

```bash
python3 -m venv .venv                # из корня репозитория
source .venv/bin/activate
pip install -r scripts/requirements.txt   # requests, beautifulsoup4, numpy, ...
```

## Порядок запуска

### База знаний

```bash
cd scripts
python fetch_wiki.py        # cargo Enemies -> data/raw/entities.json,
                            # фильтрация -> data/raw/filtered.json,
                            # HTML страниц -> data/raw/pages/ (~90 с)
python clean_html.py        # data/raw -> knowledge_base/NNN_<имя страницы>.md
                            # + entities.json (исходные имена)
python build_terms_map.py   # filtered.json -> knowledge_base/terms_map.json
python replace_terms.py     # замена терминов + переименование документов
                            # + entities.json терминами + скан остатков
python validate_dataset.py  # проверки (режим исходных/заменённых документов
                            # определяется сам), код выхода 1 при ошибке
```

Для полной пересборки нужно запустить все пять скриптов по порядку. `fetch_wiki.py --force` перезакачивает скачанные страницы.

### Векторный индекс

```bash
python build_index.py       # knowledge_base/ -> vector_store/faiss.index
                            # + vector_store/meta.json (эмбеддинги кэшируются,
                            # повторный запуск без пересчёта)
python build_index.py --test   # три тестовых запроса по готовому индексу
```

## Структура

- `common.py` -- общие пути (`data/raw`, `knowledge_base`), плановые объёмы (`EXPECTED_STATS`), конструктор regex одного термина (`compile_term_pattern`) и правило восстановления суффиксов (`replacement_value`); импортируется остальными скриптами.
- `fetch_wiki.py`, `clean_html.py`, `build_terms_map.py`, `replace_terms.py`, `validate_dataset.py` -- один скрипт на каждый этап.
- `build_index.py` -- строит векторный индекс базы знаний: чанкинг `langchain-text-splitters`, эмбеддинги bge-m3, индекс FAISS в `vector_store/` (faiss.index + meta.json); `--test` прогоняет тестовые запросы.
- `data/raw/` -- промежуточные файлы.

## Что делает каждый скрипт

### fetch_wiki.py

1. Скачивает все 203 строки cargo-таблицы `Enemies` (финское `name`, английский `alias`, `id`, `faction`, `spawnLocation`) в `data/raw/entities.json` -- источник пар «имя -> перевод» для build_terms_map.py.
2. Фильтрует:
   - мета-страницы (`Traps`, `Minä`, `Pheromone`);
   - weak/hell-варианты: id вида `<base>_weak`/`<base>_hell` (и склейка `bigfirebug`) при наличии базовой строки на той же странице, либо alias `Weak X`/`Hell X` при наличии alias `X`;
   - размерные варианты: финские префиксы `Heikko|Horna|Pikku|Pien|Suur|Iso|Jätti` (строка-база пары защищена: `Pikkutulikärpänen` с id `firebug` -- базовый светлячок, а не вариант; `Ylialkemisti` -- отдельный босс, поэтому префикс `Yli` в фильтр не входит);
   - не-существа (`Nest`, `Death Orb`, `Blood Orb`, `Crystal`) остаются в тексте, но не попадают в список сущностей;
   - страницы, где после фильтрации не остаётся ни одного существа, выбрасываются целиком.

   Результат: 149 страниц, 168 сущностей.
3. Скачивает HTML каждой страницы (`action=parse&prop=text`, пауза 0.5 с, свой User-Agent) в `data/raw/pages/`.

Итог -- `data/raw/filtered.json`: словарь страниц (slug, entities, others, removed), глобальный список терминов вариантов (`removed_terms`) и статистика (`stats`). Статистика сверяется с `EXPECTED_STATS` из `common.py`; расхождение прерывает запуск: вики изменилась, датасет перестал быть воспроизводимым.

### clean_html.py

На каждую страницу:

- удаляет шум: скрипты, стили, оглавление, navbox, сноски, картинки, пункты списков из одной внешней ссылки, секции Gallery/History/Soundtrack/References;
- удаляет контент отфильтрованных вариантов (вкладки infobox, абзацы, пункты списков и строки таблиц с их именами/alias). Чистка идёт по глобальному списку `removed_terms` из filtered.json: варианты упоминаются и на чужих страницах (See Also, проза);
- пустые секции (заголовок без текста) убираются;
- конвертирует в Markdown: заголовки, списки, таблицы, infobox -- построчно `key: value`. Для чистого markdownlint: уровни заголовков растут шагом в один (MD001), вложенные списки сдвигаются на ширину маркера (MD032/MD029), таблицы -- colspan раскрывается, строки дополняются до числа колонок, разделитель один (MD056/MD058/MD060), прямые URL берутся в `<...>` (MD034);
- пишет YAML front-matter: `source`, `title`, список `entities` (name/alias).

Скобочные синонимы `(also known as X)`, `(or X)` сохраняются: name и alias получают разные термины, и после замены фраза `термин-имя (also known as термин-alias)` сохраняет синонимику сущности.

Результат: `knowledge_base/NNN_<имя страницы>.md` (нумерация по алфавиту страниц, 149 шт.) и `knowledge_base/entities.json` (каталог файл -> сущности, исходные имена). `knowledge_base/README.md` скрипт не трогает: файл редактируется вручную.

`.markdownlint.json` в `knowledge_base/` отключает MD013 (длина строки): вики-проза идёт построчно с абзаца, а строки таблиц переносить нельзя; остальные правила по умолчанию документы проходят.

### build_terms_map.py

Строит `knowledge_base/terms_map.json` из filtered.json. Каждой сущности назначаются два термина:

- `name` -> термин-имя `<префикс> <корень>`; корни уникальны глобально;
- `alias` -> термин-alias `<корень> <роль>` -- корень тот же, что у термина-имени (связь «имя + прозвище» остаётся в тексте); одинаковые alias разных сущностей (`Goalkeeper`) получают один термин;
- `Noita` -> термин-вселенная (одно слово);
- дополнительно `Hiisi`/`Hiidet` (одно слово на оба) и заголовки групповых страниц (`Aave`, `Gate Guardian`), не совпадающие ни с одним `name`.

Генерация детерминирована: слова выбираются хешем с зерном 42 от исходного термина; префиксы и корни -- выдуманные слоги, роли -- родовые английские слова. Проверка коллизий: слова вымышленных терминов не должны совпадать с исходными (иначе проход замены найдёт их в уже заменённом тексте).

Структура словаря: `entities` (name/alias -> name_term/alias_term, флаг shared_alias, страницы), `extra_terms`, `pages` (исходный файл -> новый файл, термин заголовка), плоский `terms` для скрипта замены.

### replace_terms.py

1. Проверяет, что база ещё не заменена (имена файлов -- исходные).
2. В каждом документе удаляет строку `source:` из front-matter (URL вики раскрывает вселенную) и применяет все замены: проходы по терминам от самого длинного к короткому, границы слов `\b`, не-ASCII термины без учёта регистра, ASCII -- с учётом; английские суффиксы s/es сохраняются, финский генитив `-n` отбрасывается.
3. Переименовывает документы в `NNN_<термин-страницы>.md`.
4. Перезаписывает `entities.json` терминами (без ссылок на вики).
5. Скан остатков по всем исходным терминам + `noita`/адрес вики в любом регистре; ненулевой код выхода при остатках.

`README.md` и `terms_map.json` не заменяются: исходные термины в них нужны как документация схемы замены; при построении векторного индекса их исключить.

### validate_dataset.py

Собирает ошибки и предупреждения; ненулевой код выхода при любой ошибке. Режим определяется автоматически по составу файлов.

Исходные документы:

1. Статистика filtered.json совпадает с плановой (`common.EXPECTED_STATS`).
2. Состав файлов совпадает с отфильтрованным списком (149 шт.).
3. Front-matter каждого файла содержит все сущности своей страницы.
4. Скан остатков: термины отфильтрованных вариантов не встречаются.
5. Предупреждения: короткие тела (заглушки вики -- норма), дубликаты сущностей, файлы без упоминания сущностей.

Заменённые документы:

1. Состав файлов совпадает с `terms_map.json` (149 шт.).
2. Front-matter: title и сущности -- в терминах, строки `source` нет.
3. Скан остатков по всем исходным терминам (339 пар + термины вариантов + `noita`/адрес вики в любом регистре): остатков быть не должно.

### build_index.py

Строит `vector_store/faiss.index` (FAISS IndexFlatIP) и `vector_store/meta.json` из `knowledge_base/` (README.md и служебные json не индексируются).

1. Читает документы с разбором YAML front-matter (title, сущности страницы).
2. Режет тела на чанки `RecursiveCharacterTextSplitter` из `langchain-text-splitters`: чанк 1800 символов (около 300 слов), перекрытие 200, сепараторы `["\n## ", "\n\n", ". ", " ", ""]` с `keep_separator=True`. Каждый чанк начинается строкой с заголовком документа -- у чанков из середины секций иначе нет контекста, о какой сущности речь.
3. Кодирует чанки bge-m3 (нормализованные, batch 8). Эмбеддинги кэшируются в `scripts/data/cache/`: ключ кэша -- sha256 модели и текстов чанков, после изменения чанкинга кэш автоматически перестаёт попадать; повторный запуск строит индекс без пересчёта эмбеддингов.
4. Добавляет эмбеддинги в IndexFlatIP (векторы нормализованы, поэтому inner product эквивалентен косинусной близости) и пишет faiss.index + meta.json. В meta.json у каждого чанка: `id` (совпадает с номером строки индекса), `source`, `title`, `chunk` (позиция в документе), `entities`, полный `text`; плюс параметры модели и чанкинга, время генерации эмбеддингов.

Флаг `--test` не строит индекс заново, а кодирует три тестовых запроса (два на английском, один на русском -- проверка кросс-язычного поиска) и печатает найденные чанки со score.

## Артефакты

Все выходные файлы детерминированы и не содержат отметок времени: повторный прогон не даёт диффов. Для пересборки базы без сети достаточно закоммиченного `terms_map.json`: `clean_html.py` восстанавливает исходные документы, `replace_terms.py` применяет словарь; `fetch_wiki.py` нужен только при изменении списка страниц или словаря сущностей.
